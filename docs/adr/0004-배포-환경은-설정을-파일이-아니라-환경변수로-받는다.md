# 배포 환경은 설정을 파일이 아니라 환경변수로 받는다

`back`을 Railway에, `front-react`를 Cloudflare Pages에 올리기로 하면서 배포용 설정을 어디에 둘지 정해야 했다. 저장소가 public이므로 `application-prod.yml`에는 **값을 하나도 두지 않는다** — DB 접속 정보, JWT 서명 키, CORS 허용 출처, 샘플 데이터 비밀번호가 전부 `${...}` 참조이고 기본값이 없다. 값이 없으면 앱이 뜨지 않는다. 조용히 약한 기본값으로 뜨는 것보다 안 뜨는 편이 낫기 때문이다.

## Consequences

- `APP_JWT_SECRET`이나 `DATABASE_*`가 비면 기동이 실패한다. "왜 안 뜨지"가 "왜 뚫렸지"보다 싼 질문이다.
- `dev` 프로파일에는 기본값이 남아 있다. 로컬은 아무것도 설정하지 않아도 떠야 하고, 그 값들은 로컬에서만 유효하다.
- 설정을 바꾸려면 Railway 대시보드나 CLI를 거쳐야 한다. 저장소만 보고는 운영 값을 알 수 없다.
- `application.yml`의 기본 활성 프로파일은 여전히 `dev`다. 배포 컨테이너는 `SPRING_PROFILES_ACTIVE=prod`를 Dockerfile과 서비스 변수 양쪽에서 받는다. 둘 중 하나만 두면 실행 경로에 따라 `dev`로 떠서 파일 DB와 h2-console이 공개된다.
