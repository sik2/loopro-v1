# 04: 로그인과 인증

**What to build:** `Member`가 로그인해 토큰을 받고, 내 정보 화면에서 자기 `Nickname`과 `Role`을 확인한다. 로그아웃하면 토큰이 지워진다. 이 시점부터 읽기 요청은 누구나, 쓰기 요청은 로그인한 사람만 할 수 있다.

ADR-0002에 따라 JWT access token을 쓴다. refresh token은 없고, **로그아웃해도 그 토큰은 만료 전까지 유효하다.**

**Blocked by:** 03 (회원가입)

**Status:** ready-for-agent

- [ ] 로그인 API가 `Username`과 비밀번호를 받아 JWT access token을 낸다
- [ ] 토큰 유효기간은 7일이다
- [ ] 서명 키는 개발 프로파일에 기본값을 두되 환경변수로 덮어쓸 수 있다
- [ ] 잘못된 비밀번호는 거부한다. 이때 `Username`이 존재하는지 여부를 드러내지 않는다
- [ ] 인증 필터가 요청 헤더의 토큰을 읽어 보안 컨텍스트를 채운다
- [ ] 내 정보 API가 `Nickname`·`Role`·가입일을 낸다
- [ ] 접근 정책이 선다: 가입·로그인·읽기 요청은 인증 없이 허용, 나머지 쓰기 요청은 인증을 요구한다
- [ ] 토큰 없이 인증이 필요한 요청을 하면 401, 인증은 됐지만 권한이 없으면 403으로 구분된다
- [ ] 만료된 토큰은 거부된다
- [ ] 로그인 화면에서 로그인하면 토큰이 브라우저에 저장되고, 이후 요청 헤더에 실린다
- [ ] 401 응답을 받으면 저장된 토큰을 버리고 로그인 화면으로 보낸다
- [ ] 로그아웃하면 저장된 토큰이 지워진다
- [ ] 내 정보 화면이 `Nickname`·`Role`·가입일을 보여준다. 내가 쓴 글 목록은 이번 범위가 아니다
- [ ] 테스트가 로그인 절차를 반복하지 않고 토큰을 얻을 수 있는 공통 지원 코드가 있다
- [ ] HTTP seam 테스트: 로그인 성공 / 잘못된 비밀번호 거부 / 내 정보 조회 / 토큰 없는 요청이 401
